1. INTRODUCTION                                     *silkcircuit-introduction*

SilkCircuit is a Neovim colorscheme built on electric purples, hot pinks and
glowing cyan. It ships five variants, themes 39 plugins, and persists your
variant and glow-mode choices between sessions.

Highlights are defined for every enabled integration whether or not the
plugin is installed, so nothing has to be detected and no plugin is ever
loaded on the theme's behalf.

==============================================================================
2. REQUIREMENTS                                     *silkcircuit-requirements*

- Neovim 0.10 or later
- A terminal with true color support
- 'termguicolors' enabled

==============================================================================
3. INSTALLATION                                     *silkcircuit-installation*

Using lazy.nvim: >lua
    {
      "hyperb1iss/silkcircuit",
      lazy = false,
      priority = 1000,
      opts = {},
      config = function(_, opts)
        require("silkcircuit").setup(opts)
        vim.cmd.colorscheme("silkcircuit")
      end,
    }
<

Using packer.nvim: >lua
    use({
      "hyperb1iss/silkcircuit",
      config = function()
        require("silkcircuit").setup()
        vim.cmd.colorscheme("silkcircuit")
      end,
    })
<

Manually, with the repository on your 'runtimepath': >lua
    require("silkcircuit").setup()
    vim.cmd.colorscheme("silkcircuit")
<

Calling setup() is optional. Loading the colorscheme without it uses the
defaults below.

==============================================================================
4. CONFIGURATION                                   *silkcircuit-configuration*

Every option, with its default: >lua
    require("silkcircuit").setup({
      variant = "neon",       -- see |silkcircuit-variants|
      transparent = false,    -- skip background colors
      terminal_colors = true, -- set g:terminal_color_0 through 15
      dim_inactive = false,   -- darken windows that are not focused

      styles = {
        comments = { italic = true },
        keywords = {},
        functions = {},
        variables = {},
        operators = {},
        booleans = {},
        strings = {},
        types = {},
        constants = {},
      },

      on_highlights = nil,    -- function(highlights, colors)

      integrations = {},      -- see |silkcircuit-integrations|
    })
<

Options ~
                                                    *silkcircuit-options*

variant ~
    Which variant to load.
    Default: "neon"
    Values: "neon" | "vibrant" | "soft" | "glow" | "dawn"

    A variant passed here wins over one saved by |:SilkCircuit|. The saved
    choice applies only when setup() does not name a variant.

transparent ~
    Leave backgrounds unset so the terminal shows through.
    Default: false

terminal_colors ~
    Populate g:terminal_color_0 through g:terminal_color_15 from the variant.
    Default: true

dim_inactive ~
    Give unfocused windows a darker background.
    Default: false

styles ~
    Per syntax group attribute overrides. See |silkcircuit-styles|.

on_highlights ~
    Called with (highlights, colors) after the theme builds its table and
    before anything is applied. Mutate the table to override groups.

integrations ~
    Per plugin toggles. See |silkcircuit-integrations|.

Styles ~
                                                    *silkcircuit-styles*

Each key takes any attribute |nvim_set_hl()| accepts: bold, italic,
underline, undercurl, strikethrough, reverse, nocombine.

An attribute set to false is removed, so this genuinely turns off the
italic comments the theme ships with: >lua
    styles = { comments = { italic = false } }
<

The keys map to syntax as follows:

    comments      Comment, @comment
    keywords      Keyword, Statement, Conditional, Repeat, @keyword and
                  every @keyword.* subtype
    functions     Function, @function, @function.method
    variables     Identifier, @variable
    operators     Operator, @operator
    booleans      Boolean, @boolean
    strings       String, @string
    types         Type, @type
    constants     Constant, @constant

5. VARIANTS                                         *silkcircuit-variants*

Neon (default) ~
    The signature look. Electric purple (#e135ff) keywords on a deep violet
    background. Best for dark rooms.

Vibrant ~
    Pure magenta and pure cyan on a near-black background. The loudest of the
    dark variants.

Soft ~
    Pastel neons on a lighter violet background. Built for long sessions.

Glow ~
    Ultra-dark backgrounds with pure #ff00ff, #00ffff and #ffff00. Pure white
    text. Best on OLED.

Dawn ~
    A light variant. Deep purple and teal accents on an off-white background,
    for daytime work.

Switch at any time, and the choice is remembered: >vim
    :SilkCircuit dawn
<

==============================================================================
6. COMMANDS                                         *silkcircuit-commands*

:SilkCircuit [{variant}]                            *:SilkCircuit*
    Switch to {variant} and remember it. With no argument, print the current
    variant and the list of available ones.

:SilkCircuitGlow [on|off|toggle]                    *:SilkCircuitGlow*
    Control glow mode, which brightens functions, keywords, strings, types
    and float borders on top of the current variant. With no argument,
    toggles. The setting is remembered.

:SilkCircuitContrast                                *:SilkCircuitContrast*
    Measure every color the theme renders as text against the current
    variant's background and report anything below the WCAG AA ratio of
    4.5:1.

:SilkCircuitIntegrations                            *:SilkCircuitIntegrations*
    List which integrations are themed, which of their plugins are installed,
    and which are disabled by config.

Preferences are stored in a JSON file under |stdpath()| "data". Delete
silkcircuit_preferences.json there to forget them.

7. INTEGRATIONS                                     *silkcircuit-integrations*

SilkCircuit defines highlight groups for these 39 integrations. Every one is
enabled by default; set a key to false to skip its groups: >lua
    require("silkcircuit").setup({
      integrations = {
        telescope = false,
        noice = false,
      },
    })
<

The config keys:

    Core          treesitter, lsp (alias native_lsp), markdown
    Explorers     neotree, nvimtree, oil
    Git           gitsigns, neogit, octo
    UI            bufferline, lualine, indent_blankline, alpha, which_key,
                  telescope, fzf_lua, snacks, dropbar, lazy
    Messages      cmp, blink_cmp, notify, noice, fidget
    Motion        flash, harpoon, trouble, grug_far
    Tools         mason, mini, dap (alias nvim_dap), neotest, aerial, avante
    Visual        rainbow_delimiters, render-markdown, treesitter_context
    Windows       ufo, window_picker

Highlights load for every enabled integration whether or not the plugin is
present. Defining a group for an absent plugin costs nothing, and it means
the theme never has to require a plugin to decide.

                                                    *silkcircuit-auto_detect*
The auto_detect option is accepted and does nothing. Detection is passive
now, reads only package.loaded, lazy.nvim's own spec and the runtimepath,
and is used only by |:SilkCircuitIntegrations| and |:checkhealth| to report
what is installed.

Lualine ~

A matching lualine theme ships with the colorscheme: >lua
    require("lualine").setup({ options = { theme = "silkcircuit" } })
<

It rebuilds from the active variant, so it follows |:SilkCircuit|.

8. CUSTOMIZATION                                   *silkcircuit-customization*

Override any highlight group through on_highlights: >lua
    require("silkcircuit").setup({
      on_highlights = function(hl, c)
        hl.CursorLine = { bg = c.bg_highlight }
        hl.Search = { fg = c.bg, bg = c.yellow }
        hl["@comment"] = { fg = c.gray, italic = true }
      end,
    })
<

The colors table holds the active variant's palette. Every value is a solid
six digit hex string or "NONE", never an alpha form, because |nvim_set_hl()|
rejects those.

Backgrounds    bg, bg_dark, bg_darker, bg_highlight, bg_float,
               bg_statusline, bg_visual
Foregrounds    fg, fg_dark, fg_light, fg_gutter
Grays          gray, gray_light, gray_dark, gray_muted
Accents        purple, purple_dark, purple_muted, pink, pink_bright,
               pink_soft, cyan, cyan_bright, cyan_light, green,
               green_bright, green_light, blue, blue_bright, blue_light,
               blue_gray, yellow, yellow_bright, yellow_light, coral,
               orange, red, red_dark, red_error
Roles          keyword, string, operator, comment, border
Selection      selection, selection_highlight, selection_inactive,
               word_highlight, word_highlight_strong
Diagnostics    error, warning, info, hint
Git and diff   git_add, git_change, git_delete, diff_add, diff_change,
               diff_delete, diff_text
Glow           glow_pink, glow_purple, glow_cyan
Terminal       terminal_black through terminal_bright_white

9. LUA API                                          *silkcircuit-api*

require("silkcircuit").setup({opts})                *silkcircuit.setup()*
    Merge {opts} over the defaults. Optional.

require("silkcircuit").load()                       *silkcircuit.load()*
    Apply the theme. This is what colors/silkcircuit.lua calls.

require("silkcircuit").colorscheme()               *silkcircuit.colorscheme()*
    Alias for load().

require("silkcircuit").get_colors()                 *silkcircuit.get_colors()*
    Return the active variant's color table.

require("silkcircuit").compile()                    *silkcircuit.compile()*
    Deprecated no-op. The compiled cache was removed in v2; a full load with
    every integration takes a few milliseconds without it.

AstroNvim users can feed the palette to AstroUI's status system: >lua
    status = {
      colorscheme = "silkcircuit",
      colors = require("silkcircuit.contrib.astronvim").status_colors,
    }
<

10. TROUBLESHOOTING                              *silkcircuit-troubleshooting*

Start here: >vim
    :checkhealth silkcircuit
<

Colors look wrong or washed out ~
    Set 'termguicolors' and confirm your terminal does true color. The theme
    refuses to load without 'termguicolors' and says so.

A plugin is not themed ~
    Check |:SilkCircuitIntegrations| for the integration name, then confirm
    it is not set to false in your config. If the plugin has no integration,
    open an issue.

The wrong variant loads ~
    A variant saved by |:SilkCircuit| applies when setup() does not name one.
    Pass variant explicitly to setup() to pin it, or delete
    silkcircuit_preferences.json from |stdpath()| "data".

Diagnosing a load ~
    Set vim.g.silkcircuit_debug = true before the colorscheme loads to get
    timing on every load.

==============================================================================
11. CONTRIBUTING                                    *silkcircuit-contributing*

Issues and pull requests:
    https://github.com/hyperb1iss/silkcircuit

Adding an integration:
    1. Create lua/silkcircuit/integrations/{name}.lua returning a module with
       get(colors, opts) that returns a table of highlight groups.
    2. Add an entry to the registry in integrations/init.lua and a key to the
       integrations defaults in config.lua.
    3. Use only palette keys, never literal hex, and never an alpha form.
